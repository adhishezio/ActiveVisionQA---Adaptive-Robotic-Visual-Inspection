## Locally generated material

`activevisionqa/assets.py` generates the table, manufactured-part-like box and occluders in SDF. The marking uses OpenCV's predefined `DICT_4X4_50` dictionary; ID 7 is the expected part identifier and ID 23 is a controlled wrong-identifier case. The simulator renders the binary cells as flat native visual geometry, avoiding engine-specific texture handling. A PNG marking preview is generated alongside the world.

All fixture images are generated by `activevisionqa/fixtures.py` from declared seeds. They are synthetic diagnostics, not examples of validated real factory defects. No employer/customer data, external image dataset or pretrained model is used.

The text dataset extension uses OpenCV's built-in `FONT_HERSHEY_SIMPLEX` glyph renderer, then creates flat native Gazebo ink geometry. No separate font asset is downloaded or vendored. Texts, part geometry and scene variations are generated locally from the saved plan. The resulting images are synthetic printed-label-like scenes, not validated engraved industrial components. This extension adds no runtime dependency beyond the existing OpenCV/NumPy/Pillow and ROS packages.

The OCR extension uses the installed OpenCV HOG descriptor and `cv2.ml.SVM`. Its character and whole-word training images are generated locally; model bundles record source/data/artifact hashes and the OpenCV version. No pretrained weights, external OCR service, additional font file, PyTorch package or external dataset is downloaded. See `docs/OCR.md` for training scope and limitations.

## Runtime environment

The ROS demo uses Ubuntu system Python and OpenCV. It does not require CUDA Python packages. Camera rendering uses Gazebo's graphics stack; actual GPU acceleration on the development WSL setup remains unverified.
